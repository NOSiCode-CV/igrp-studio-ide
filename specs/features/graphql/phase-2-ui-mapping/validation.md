# Phase 2: GraphQL UI Mapping Validation

## Automated Validation

Automated checks should verify mapping functions and UI-to-manifest normalization.

Checks:

- Query form data maps to `operationType: "query"` and excludes `inputType` and `eventTopic`.
- Mutation form data maps to `operationType: "mutation"` and includes `inputType`.
- Subscription form data maps to `operationType: "subscription"` and includes `eventTopic`.
- Existing operation `id` is preserved after edit and rename.
- New operation `id` is not generated by form state.
- Delete and update actions target operations by `id`.
- Transient UI-only fields are removed before persistence.
- `operationType` values are lowercase.
- `returnMode` values remain `single` or `list`.

Expected result:

- UI-originated data can be transformed into the Phase 1 manifest shape.
- UI-originated data is sanitized and then passed to canonical validation before persistence.

## Manual Validation

### Create Query From UI Model

Create a query using the UI model with name, comment, arguments, return type, and return mode.

Expected result:

- Persisted JSON contains a query operation with `id`, `operationType`, `name`, `comment`, `args`, `returnType`, and `returnMode`.
- Persisted JSON does not contain `inputType` or `eventTopic` for the query.

### Create Mutation From UI Model

Create a mutation using the UI model with input type, arguments, return type, and return mode.

Expected result:

- Persisted JSON contains `operationType: "mutation"` and an `inputType`.
- Persisted JSON does not contain `eventTopic`.

### Create Subscription From UI Model

Create a subscription using the UI model with event topic, arguments, return type, and return mode.

Expected result:

- Persisted JSON contains `operationType: "subscription"` and `eventTopic`.
- Persisted JSON does not contain `inputType`.

### Rename Operation

Rename an existing operation.

Expected result:

- `name` changes.
- `id` remains unchanged.
- The open editor remains associated with the same operation.

### Reject REST Fields

Attempt to persist UI data containing REST-only fields.

Expected result:

- Sanitization removes unsupported UI-originated fields before canonical validation.
- The manifest remains GraphQL-only.
